## Why this exists

Every library in this TRD can pass its own unit tests while nothing calls it.
AC-023-1 is the rule against exactly that. A capability counts as reachable
only when a chain holds end to end:

```
entry command TEXT  ->  skill  ->  CLI subcommand registered in HANDLERS
```

Break any one link and the capability is unreachable, however green its own
tests are. The grader refuses prose that merely *names* a subcommand: only a
real invocation (`node "$PR_REVIEW_CLI" <subcommand>`) counts as a call.

## AC-023-1 — reachable from the real entry points

The three behaviours REQ-023 names map to the subcommands that implement them
in the TRD data flow:

| Capability | Subcommands that must be reached |
|---|---|
| `verified-findings` | `votes` |
| `convergence` | `status` + `ledger` + `scope` |
| `tier` | `tier` |

Convergence requires **all three**: a round cap without repeat suppression
still loops on the same finding, and neither converges without the delta
re-review range. Partial evidence is reported as unreachable with the missing
piece named — never rounded up to "reached".

Result for this checkout:

| Entry point | Reaches the skill | verified-findings | convergence | tier | Direct CLI calls |
|---|---|---|---|---|---|
| `fix-issue` (`packages/development/commands/fix-issue.yaml`) | `pr-review-cycle` | reached | reached | reached | none |
| `implement-trd-beads` (`packages/development/commands/implement-trd-beads.yaml`) | `pr-review-cycle` | reached | reached | reached | none |
| `pr-merge` (`packages/git/commands/pr-merge.yaml`) | `pr-review-cycle` | reached | reached | reached | none |

"Direct CLI calls: none" is a second, independent check. The TRD integration
contract is that callers invoke the skill and never the CLI; a direct call
would bypass the procedure this proof is about, so it is reported as a
boundary violation **and** never counted as reachability.

## AC-023-2 — the four runtimes, and what is reduced

Claude is the baseline. Equivalence is one-directional: a runtime must carry
everything the baseline carries, but carrying more is not a reduction.

| Runtime | Procedure skills | CLI subcommands | Equivalent? |
|---|---|---|---|
| Claude (`packages/development`, `packages/git`, `packages/quality`) | `pr-review-cycle`, `pr-review-eval`, `pr-review-explainer`, `pr-review-sweep` | 24 | baseline |
| Pi (`packages/pi`) | all four, generated copies | 24, vendored at `packages/pi/vendor/lib/` | **yes** |
| Codex (`packages/codex/.codex`) | none | none vendored | **no — reduced** |
| OpenCode (generated `dist/opencode/.opencode`) | none | none vendored | **no — reduced** |

### Stated reduction (the AC's own escape hatch)

**Codex and OpenCode are reduced.** Both generate the `fix-issue`,
`implement-trd-beads` and `pr-merge` command artifacts, so a user on those
runtimes still gets the entry points. Neither bundles the `pr-review-cycle`
procedure skill, the other three `pr-review-*` skills, or a vendored
`pr-review-cli.js`. The cause is in the generators, not in this TRD:

- `scripts/generate-codex/index.js` rewrites a **fixed framework list**
  (`react`, `nestjs`, `rails`, `phoenix`, `blazor`, `dotnet`, `jest`,
  `pytest`, `rspec`, `xunit`, `exunit`) into `.codex/skills/`. Procedure
  skills are not in that list.
- `scripts/generate-opencode` copies `packages/<pkg>/skills/<pkg>/SKILL.md`, the
  one skill a package names after itself. The multi-skill
  `packages/development/skills/<name>/SKILL.md` layout is not discovered.

**Consequence for a user on Codex or OpenCode.** The generated `pr-merge`
artifact still instructs the agent to invoke the `pr-review-cycle` skill at
`packages/development/skills/pr-review-cycle/SKILL.md`. That path resolves
only if the monorepo (or the Claude/Pi plugin) is also present. Where it is
not, the verified-findings, convergence and tier behaviour is **not
available**, and the merge gate degrades to the command's own CI and
`reviewDecision` conditions.

This is reported rather than fixed here: extending either generator to carry
procedure skills is a packaging change beyond TRD-037's scope, and silently
claiming equivalence would be the exact failure REQ-006 and AC-023-2 are
written to prevent.

## AC-023-3 — no new CI secret

The in-agent review completes with **no secret this TRD introduced**. Secrets
referenced by review workflows in this checkout:

| Secret | Status | Evidence |
|---|---|---|
| `GITHUB_TOKEN` | pre-existing | injected by GitHub Actions; never configured by anyone |
| `CLAUDE_CODE_OAUTH_TOKEN` | pre-existing | added with `.github/workflows/claude-code-review.yml` in `3765f11` (2025-12-29), ~10 months before this TRD |

The structural reason no new secret is needed: every graded fact is a pure
local CommonJS module. The suite asserts that no `pr-review-*` library (other
than the CLI dispatcher and the state module that owns file I/O) requires
`http`/`https`/`net`/`child_process`, calls `fetch`, or reads a
`process.env.*TOKEN|KEY|SECRET`. With the hosted reviewer **not** configured,
the proof records `hosted-reviewer-not-configured` as a note and the in-agent
review still runs — which is what AC-023-3 promises.

## AC-024-2 — a credential is never reproduced

A token-shaped value is pushed **through** each library's real entry point and
the output is searched for it — nested values, array elements and object keys
alike. This measures the output paths that can carry a credential to a
finding, comment or ledger entry; it does not merely inspect the redaction
helper.

Libraries sampled: `pr-review-ledger` (`normalizeFinding`, `recordResolution`
success path **and refusal path**), `pr-review-state` (`redact`),
`pr-review-votes` (`tallyVotes`). Result: **no leaks**.

A defect this proof found and fixed: `recordResolution` echoed the caller's
finding back **unredacted** on its two refusal branches. A refusal is still an
output a skill may put in a report or a comment, so a credential inside a
malformed request could ride out on the error path — the one route that
bypassed every redaction on the success path. Both branches now redact.

## How to re-run

```bash
npx jest packages/development/tests/pr-review-reachability.test.js \
         packages/development/tests/pr-review-reachability-repo.test.js
```

The grader is also reachable as a subcommand, so a maintainer can run it over
their own inventory:

```bash
echo '{"action":"trace","entryPoints":[...],"skills":[...],"subcommands":[...]}' \
  | node packages/development/lib/pr-review-cli.js reachability
```

`action` selects the grader: `trace` (AC-023-1), `runtimes` (AC-023-2) or
`secrets` (AC-023-3, AC-024-2).
