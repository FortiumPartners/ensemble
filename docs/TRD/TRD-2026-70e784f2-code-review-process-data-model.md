## Overview

No database, schema migration or durable service is introduced (Constitution Rule 4). Every record is a plain file or a JSON value passed on stdin/stdout between the `pr-review-cycle` skill and `pr-review-cli.js`. Policy and rules are user-owned files in the reviewed repository; the review-state report stays untracked under `.ensemble/pr-review/`; eval cases are repository data owned by code owners.

## Entities

### Review policy (policy block in root `REVIEW.md`)

A fenced `ensemble-review-policy` JSON block.

| Field | Type | Default | Notes |
|---|---|---|---|
| `roundCap` | integer 1-5 | 3 | Single cap for every review procedure (REQ-009) |
| `depth` | object | Quick 1/0, Standard 2/3, Deep 2/5 (reviewers/verifiers) | Bounds only; Quick may not exceed one reviewer and zero verifiers |
| `sliceLines` | integer | 1500 | Changed lines above which a PR is reviewed by area |
| `botLogins` | string[] | `[]` | Plus platform-marked bots |
| `maintainers` | string[] | `[]` | Eligible for the Low waiver |
| `sensitive` | string[] globs | built-in default set | Merged with the defaults |
| `high` | string[] globs | `[]` | Forces High tier |
| `lowWaiver` | `{ enabledBy, enabledAt }` or null | null | Set only by a code owner after the evidence rule is met |
| `evalCasesDir` | string | `docs/review-eval/cases` | Directory holding eval case files |

### Area rules file (`REVIEW.md`, any directory)

Free markdown. Guidance only; policy keys in non-root files are ignored with a warning.

### Ledger finding (extends the 82b6a138 finding)

Existing fields: `id`, `source`, `locationOrLink`, `severity`, `failureMode`, `disposition`, `evidence`, `originalTextOrLink`. Added:

| Field | Type | Notes |
|---|---|---|
| `tag` | `important` \| `nit` \| `pre-existing` | Closed set; legacy `severity` values map in |
| `lane` | `bug` \| `security` | Security lane findings block while open |
| `fingerprint` | string | Normalized path + failure mode + class; drives repeat suppression |
| `class` | `{ classId, instances[] }` \| null | Class-of-bug record |
| `votes` | `[{ verifier, verdict }]` | `real` \| `not-real` \| `abstain` |
| `outcome` | `present` \| `filtered` \| `disputed` \| `unverified` | From `tallyVotes` |
| `resolution` | `{ decision, reason, by, at, headSha }` \| null | Required to close without a fix |
| `reviewer` | string | Excluded from its own verifier set |

### Review-state report (extends the 82b6a138 report)

Added: `tier` `{ tier, effectiveTier, reasons[], raised[{ from, to, reason }], assignedBy }`, `depth` `{ mode, reviewersUsed, verifiersUsed }`, `verification` `{ performed, reason }`, `remediationShas[]` (commits created by the batch fix, used to vouch for history), `roundCap`, `rulesApplied[]`.

### Approval evaluation (transient JSON)

`{ required, counted[{ login, commit, tree }], ignored[{ login, reason }], satisfied }` where `reason` is `automated` or `stale-commit`.

### Eval case (file `docs/review-eval/cases/<id>.json`, or `<evalCasesDir>/<id>.json`)

| Field | Type | Notes |
|---|---|---|
| `id` | string | |
| `change` | commit or PR reference | The change that caused the incident or revert |
| `bug` | string | What went wrong |
| `location` | `{ path, startLine, endLine }` | Where the bug lived |
| `confirmedBy` | login | Must be a code owner of `location.path` |
| `rulesFile`, `rulesHash` | string | The area rules in force; a changed hash marks the case stale |

### Metrics cohort input (transient JSON)

Array of merged-PR records: `{ number, author, createdAt, mergedAt, reviews[{ login, isBot, state, commit, submittedAt }], commits[], reviewRequests[], responses[{ findingId, class }] }`, plus `reverts[]` and `incidents[]`. Cohort output: median and p95 values, rates and a `guardrail` result.

### Baseline result file (committed, `docs/guides/review-baseline-<date>.json`)

Output of the baseline capture runbook (TRD-044): the metric set from the metrics cohort output (median and p95 human approvals, human comments, wait-on-human hours, rounds-to-pass, share needing 5+ rounds, noise rate, reverts, incidents), plus the cohort window, size and the queries used. It is reviewable in git, later comparisons read it as the baseline, and the metrics library must reproduce its numbers from the same inputs.

### Tier classifier and second-assessment contract (transient JSON)

`kinds[{ kind, paths[] }]` with `kind` in `docs | copy | additive-behind-flag | product | other` (missing, unknown or uncited = `other`) and `secondAssessment { needsAnotherPerson, reason, evidencePaths[] }` (exactly `true` raises one level; any non-boolean value is treated as `true`).

## Relationships

- A review-state report has one policy snapshot reference (`sourceSha`) and many ledger findings.
- A ledger finding has zero or more votes, zero or one class record, zero or one resolution.
- An eval case maps to one area rules file and one code owner via CODEOWNERS.
- A metrics cohort aggregates many PRs; findings link to responses by `findingId`.

## Data Ownership

| Data | Owner | Stored where |
|---|---|---|
| Policy block, area rules, sensitive paths | Repository code owners | Files in the reviewed repository, read from the base commit |
| Ledger, votes, tier record | The review run for one PR head | `.ensemble/pr-review/<key>.json`, untracked and gitignored |
| Eval cases | Code owner of the affected area | `docs/review-eval/cases/<id>.json` (tracked in git; directory set by `evalCasesDir`) |
| Baseline result | The maintainer who captured it | `docs/guides/review-baseline-<date>.json`, committed |
| Metrics inputs and post-change outputs | Whoever runs the guide's `gh` queries | Not persisted by ensemble |

## Migration/Backfill Notes

- Existing ledgers with `critical`/`major`/`minor`/`nitpick` are mapped at read time (critical, major to `important`; minor, nitpick to `nit`); no rewrite is required (AC-007-4).
- Existing review-state reports without the new fields are read with those fields absent; the absence is treated as "no tier recorded" and the strict default applies.
- `MAX_AUTO_ROUNDS = 2` in status facts is replaced by `roundCap`; reports written with `rounds.max = 2` keep that value for display only.

## Validation Rules

- `roundCap` is an integer from 1 to 5; any other value is ignored with a warning and 3 applies.
- A policy whose `sourceSha` differs from `baseSha` is rejected and strict defaults apply.
- Unknown policy keys and wrong types are rejected by name; nothing in a policy is executed.
- A finding's `tag` is in the closed set; an unrecognised legacy severity is treated as `important` (actionable).
- A verifier may not appear on a finding it produced; a vote outside `real|not-real|abstain` is not a vote.
- A tier may only be raised by an agent; lowering requires a code owner. A Low result is effective Low only when the waiver is enabled and at least 20 Low PRs over 30 days have merged with zero reverts and incidents.
- An eval case is valid only when `confirmedBy` is a CODEOWNERS owner of `location.path`.
- A cohort under 20 PRs or 30 days is insufficient for comparison.

## Privacy/Security Notes

- Rules, policy and sensitivity declarations are read from the base commit so a PR cannot weaken its own review.
- Values matching credential patterns (tokens, keys, `Authorization` headers) are redacted before any finding, resolution reason or report is written.
- Logins in approvals and metrics are public repository identities already present in GitHub review data; no other personal data is collected.
- The review-state report is untracked so it cannot alter the head it describes.
